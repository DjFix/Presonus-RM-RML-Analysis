# SQLite-backed symbol tracker

`generate_symbol_tracking.py` reads both ready and declaration-pending records
from one read-only SQLite snapshot selected by
`validation/registry-sqlite/ACTIVE.json`. Retired readiness JSON files are
historical snapshots; there is no production fallback to them. A missing or
unsupported database fails closed.

Run from the project root. The ordinary tracker command still generates the
same role tables, coverage JSON and `SYMBOLS.md`:

```sh
uc-library/.venv/bin/python uc-library/tools/generate_symbol_tracking.py --library uc-library --repository .
```

An explicit database override is absolute or relative to the **library**. Use
an isolated output directory and timing receipt for review without changing
canonical tracker output:

```sh
uc-library/.venv/bin/python uc-library/tools/generate_symbol_tracking.py --library uc-library --repository . --registry-db /absolute/project/uc-library/validation/registry-sqlite/runs/generation/operational.sqlite --output-root temp/tracker-review --timing temp/tracker-review-timing.json
```

The shared adapter reconstructs original entry metadata and ordered source maps
from normalized tables, loading each source set once. The consumer borrows
these maps read-only. Ready records still require the original current proof
hash, unchanged `proof_covers` predicate, every library source hash, explicit
repository-relative Core source boundary and hashes, and current formatter
configuration/source coverage. Pending records retain their original exact
ELF/name/compiled/mangling membership and source/proof checks. Tasks never grant
readiness. Integration source/log hashes, pinned upstream source mapping,
original ELF hashes, every exported symbol's file-offset byte slice and hash,
pseudocode warning/index hashes, aliases, NOBITS and deferred Core policy all
retain their existing checks and output meaning.

One operation-local cache freshly hashes each file, caches resolved paths,
retains at most eight parsed JSON documents, and performs final path/stat
unchanged checks. Repeated source/repository/formatter predicates are evaluated
once per borrowed immutable source-map identity. Strong references prevent
object-ID reuse. No evidence result is persisted or trusted across operations.
The timing receipt records the tool hash, SQLite snapshot provenance, unique
hashed files/source sets and elapsed seconds. A changed source or symlink
invalidates the final guard.

`--output-root` changes only destinations; all scope/config/proof/ELF inputs
still come from `--library` and the supplied original firmware location.
Generated table links retain their canonical relative form. The one intended
prose change identifies ACTIVE.json/SQLite as authority and the old JSON ledgers
as historical; symbol entries/statuses/proof links/ranges and coverage values
must otherwise match a source-equivalent baseline.

Tests use independent project-local fixtures and databases. They compare every
generated byte between injected historical registry documents and actual
SQLite, deliberately poison retired JSON ledgers to rule out fallback reads,
verify changed source/proof/repository rejection, retain byte-range/export
failures, and exercise dirty-file and retargeted-symlink cache guards:

```sh
uc-library/.venv/bin/python -m unittest discover -s uc-library/tools -p test_generate_symbol_tracking_sqlite.py -v
```

Actual timing/parity receipts are retained in the coordinator's versioned
`evidence/recovery/` cutover directory. Full checks remain mandatory: an old
administrative tool path whose sealed bytes changed correctly loses its status
until an explicitly audited continuation resolves that binding. Caching does
not excuse such a mismatch.
