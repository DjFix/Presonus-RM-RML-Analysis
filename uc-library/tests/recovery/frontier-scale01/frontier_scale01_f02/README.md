Controller constructor bounded source-port replay

The saved research producer runs the two separate original 80-byte ARM ranges,
30 cases each. oracle.py redirects its outputs into assigned scratch without
changing historical evidence. fixtures.json contains that fresh run. replay.py
compares each native object's named initialized slots against the executable.
Opaque native pointer bits are mapped to a valid borrowed C++ list or null;
invalid portable pointers are excluded. Native padding at 30/31 is untouched;
the portable model exposes no padding representation. The compiler owns its vptr,
and native table address 0x35d300 is never installed in portable objects.

The driver also checks the independent live CCL-vector adapter through growth,
index and tag normalization. This adapter check is a source integration check,
not original constructor behavior. No original IController inheritance, full
virtual order, field declarations, destructor semantics, binary compatibility,
ARM ABI or hardware behavior is claimed. Both constructor symbols are inspected
in the actual executable; native entries are distinct, while compiler-generated
portable C1/C2 entries may alias. Construction is through a concrete test subclass;
production Controller stays abstract. Native constructors make no calls.

Local checks are checks.py format/compile/symbols/replay from the repository root.
Root may include this CMakeLists after enabling Python3 and testing; it links the
canonical facade instead of duplicating production translation units. Fixture
identity is recorded in HANDOFF.json. No ready/pending fragment is delivered.
