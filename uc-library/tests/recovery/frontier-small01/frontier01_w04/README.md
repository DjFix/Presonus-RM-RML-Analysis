# Bounded control, message and lifecycle source ports

All eight original identities are CS18AI surface 13840, exact ELF SHA-256
304c6cd1f7b4319c4f82ceaa241ab59736a0a6a8495dc2a980d855ec5aa449a0.
Each sealed packet supplies an independently checked section/range. The native
oracle executes application instructions through return, intercepting external
MappingTable, sendMidiMessage or Component destruction. It never executes Core
instructions. Native D1 vptr writes are retained as observations; portable C++
vptr addresses, extra original bases and original layout are not equated.

Controls require a live borrowed readable 44-byte record array ending with a
zero first byte, and a real MappingTable binding for every eligible entry. Names
must be NUL-terminated within each record and live through each mapping call.
Only byte 37 determines eligibility. The array pointer is reread after mapping
callbacks; replacements must provide the still-to-be-visited indices and a
terminator. Native and C++ fixtures cover empty/single/mixed/early-terminated
lists, 0/1/128/255 eligibility, both bool values and callback pointer replacement.
The C++ replay uses actual MappingTable lookup and setControlEnabled; only opaque
Item operations are test doubles, explicitly outside the production provider.

Connection messages cover both bool values and 68 eight-byte identities,
including high-bit boundaries and deterministic random values. Native
sendMidiMessage is an intercepted call boundary; the portable method uses the
actual existing production sendMidiMessage implementation and captures its
physical-output callback. First identity byte is preserved, seven others are
masked to 7 bits. No physical MIDI or GUI dispatch validation is claimed.

Six partial classes use actual pinned CCL 5.0.0 Component cleanup. Independent
baseline observations execute Component directly, then compare each app class
for masks 0..7 selecting ordinary children and array-owned children. Destruction
order and actual ordinary-child deallocation counts are observed. These source
provider observations are separate from native application D1 boundary evidence.
Original complete inheritance, fields, vtables, ownership outside the selected
app bodies, ARM ABI and binary interoperability remain unresolved. Native D0,
D2 and compiler thunks are outside this assignment, even when the host compiler
emits them. Ordinary method return choices are source-port choices, unresolved
as original declarations; all eight are proposed compiled-pending.
